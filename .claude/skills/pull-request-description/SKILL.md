# pull-request-description

## 說明

根據專案的 PR 模板（.github/pull_request_template.md）自動生成可直接貼到 GitHub PR 的描述內容。Claude 會分析當前分支的變更，產出符合模板格式的 PR 描述。

## 觸發條件

當使用者需要建立 PR 描述時啟動，常見情境：

- 使用者說「幫我寫 PR 描述」、「產生 PR description」
- 使用者說「準備發 PR」、「要 merge 了，幫我寫描述」
- 使用者直接呼叫 `/pull-request-description`

---

## SOP 流程

### Step 1: 收集變更資訊

**執行以下指令取得所有變更（已 commit + 未 commit）：**

```bash
# 取得當前分支名稱
git branch --show-current

# 取得已 commit 的變更（與 main 比較）
git log main..HEAD --oneline

# 取得所有變更（已 commit + 未 commit）與 main 的差異
# 包含 staged 和 unstaged 的變更
git diff main --name-status
git diff main --stat

# 取得未追蹤的新檔案列表
git ls-files --others --exclude-standard
```

**注意**：分析時要同時考慮：

- 已 commit 到當前分支的變更
- 已 staged 但未 commit 的變更
- 未 staged 的變更
- 新增但未追蹤的檔案

---

### Step 2: 分析變更類型

根據變更的檔案與內容，判斷屬於哪些類型（可複選）：

| 變更類型         | 判斷依據                                                          |
| ---------------- | ----------------------------------------------------------------- |
| 新增或刪除程式碼 | 新增/刪除 `.ts`, `.tsx`, `.js`, `.jsx` 等程式碼檔案               |
| 調整商業邏輯     | 修改 routes、services、handlers、utils 中的邏輯                   |
| 優化與重構       | 重新命名、拆分檔案、改善程式碼結構、效能優化                      |
| 調整畫面         | 修改 components、pages、styles、CSS、Tailwind                     |
| 調整設定檔       | 修改 `package.json`, `tsconfig.json`, `.env`, `vite.config.ts` 等 |

---

### Step 3: 撰寫描述內容

根據 commit 訊息與程式碼差異，撰寫清楚的描述：

- **使用條列式格式**：1. XXXX, 2. XXXX, 3. XXXX
- **主要說明做了什麼**（功能面）
- **解決什麼問題或需求**（目的面）
- **調整了哪些檔案/模組**（範圍面）

---

### Step 4: 判斷測試方式

根據變更內容判斷測試方式：

- 若有 UI 變更 → 需要手動測試
- 若有 API 變更 → 需要手動測試或自動化測試
- 若僅設定檔變更 → 確認建構/啟動正常

---

### Step 5: 輸出格式

**必須完全遵守專案 PR 模板的格式**，輸出以下內容：

**Checkbox 格式說明：**

- 已勾選：`- [x]` （dash + 空格 + 左方括號 + x + 右方括號，x 前後沒有空格）
- 未勾選：`- [ ]` （dash + 空格 + 左方括號 + 空格 + 右方括號）

**⚠️ 重要：每個選項前面都必須有 `[ ]` 或 `[x]`，不可以只有 `- 選項名稱`**

**完整範例輸出（基於真實 PR 情境）：**

```markdown
### 描述該 PR 的細節

<!-- 請描述這個 PR 做了什麼、解決什麼問題，或調整什麼檔案 -->

1. 修正後端 menu-sets API 的 N+1 查詢效能問題，將原本逐筆查詢改為批次查詢（使用 `inArray`），大幅降低資料庫查詢次數
2. 在回傳的 dishes 資料中新增 `name` 和 `ingredientsText` 欄位，提供更完整的菜色資訊

### PR 調整

<!-- 請勾選本次 PR 涵蓋的調整類型（可複選） -->

- [x] 新增或刪除程式碼
- [x] 調整商業邏輯
- [x] 優化與重構
- [ ] 調整畫面
- [ ] 調整設定檔

### 測試

<!-- 請勾選本次 PR 的測試方式 -->

- [x] 手動測試
```

**輸出檢查清單（必須全部符合）：**

- ✅ 描述使用條列式格式（1. XXXX, 2. XXXX, 3. XXXX）
- ✅ 每個 checkbox 選項前面都有 `- [ ]` 或 `- [x]`（**不是** `- 選項名稱`）
- ✅ 已勾選使用 `[x]`（x 是小寫，前後沒有空格）
- ✅ 未勾選使用 `[ ]`（中間剛好一個空格）
- ✅ 保留所有 HTML 註解（`<!-- ... -->`）
- ✅ 描述內容具體說明做了什麼、解決什麼問題
- ✅ 根據實際變更內容決定要勾選哪些項目

**錯誤示例（千萬不要這樣輸出）：**

```markdown
### PR 調整

- 新增或刪除程式碼 ❌ 缺少 [ ] 或 [x]
- [x] 調整商業邏輯 ❌ X 必須小寫
- [x ] 優化與重構 ❌ x 後面不可有空格 -[x] 調整畫面 ❌ dash 後面必須有空格
```

---

## 輸出規範

1. **格式必須與模板完全一致**：包含標題、註解、checkbox 格式
2. **Checkbox 格式嚴格遵守**：
   - 已勾選：`- [x]` （dash + 空格 + 左括號 + x + 右括號）
   - 未勾選：`- [ ]` （dash + 空格 + 左括號 + 空格 + 右括號）
   - **錯誤示例**：`- [x/空格]`、`-[x]`、`- [X]`
3. **描述使用繁體中文**：與專案風格一致
4. **保留模板中的 HTML 註解**：方便使用者理解各區塊用途
5. **直接可貼上**：輸出內容可直接複製貼到 GitHub PR 描述欄位

---

## 限制

1. **不自動發 PR**：僅輸出描述文字，由使用者自行貼上
2. **不擅自推測未變更的內容**：僅根據實際 git diff 結果分析
3. **若無法判斷**：詢問使用者補充說明

---

## 快速指令

若使用者只說「幫我寫 PR 描述」，直接進入 Step 1 收集變更資訊並產出結果。
