## 第一步：需求分析與規格定義

### 💭 思考過程

**首先問自己：這個功能要做什麼？**

1. **核心需求**：
   - 用戶可以收藏喜歡的菜譜
   - 用戶可以查看自己的收藏列表
   - 用戶可以取消收藏

2. **業務規則**：
   - ✅ 每個人只有一個收藏列表
   - ✅ 同一個菜譜只能收藏一次（不能重複收藏）
   - ✅ 只能看到自己的收藏（資料隔離）
   - ✅ 收藏時要確認菜譜存在

3. **API 端點設計**：
   ```
   GET    /api/favorites           - 查看收藏列表
   POST   /api/favorites           - 新增收藏
   DELETE /api/favorites/:recipeId - 取消收藏
   ```

- 請求格式

## 第二步：資料庫設計

### 💭 思考過程

**問題：如何在資料庫中表達「收藏」這個關係？**

#### 關鍵思考點：

1. **這是什麼類型的關係？**
   - 用戶 ↔ 菜譜 是「多對多」關係
   - 一個用戶可以收藏多個菜譜
   - 一個菜譜可以被多個用戶收藏

2. **多對多關係怎麼設計？**
   - 需要一個「中間表」（關聯表）
   - 這個表叫 `favorites`
   - 儲存：誰（user_id）收藏了什麼（recipe_id）

3. **需要哪些欄位？**

   ```
   favorites 表：
   - id          → 主鍵（每一筆收藏的唯一識別）
   - user_id     → 誰收藏的（外鍵 → user 表）
   - recipe_id   → 收藏什麼（外鍵 → recipes 表）
   - created_at  → 什麼時候收藏的
   ```

4. **重要的約束條件**：
   - **UNIQUE(user_id, recipe_id)**：防止同一個人重複收藏同一個菜譜
   - **ON DELETE CASCADE**：如果用戶或菜譜被刪除，收藏記錄也自動刪除

### 📝 實作步驟

#### 2.1 定義 Drizzle ORM Schema

在 `src/db/schema.ts` 中：

```typescript
// Favorites 表（收藏）
export const favorites = pgTable(
  'favorites',
  {
    id: text('id')
      .primaryKey()
      .$defaultFn(() => createId()), // 自動生成 ID
    userId: text('user_id')
      .notNull()
      .references(() => user.id, { onDelete: 'cascade' }), // 外鍵 + 級聯刪除
    recipeId: text('recipe_id')
      .notNull()
      .references(() => recipes.id, { onDelete: 'cascade' }),
    createdAt: timestamp('created_at', { mode: 'date' }).defaultNow().notNull()
  },
  (table) => [
    // 建立索引，加速查詢
    index('idx_favorites_user').on(table.userId),
    index('idx_favorites_recipe').on(table.recipeId),
    // 唯一約束：一個人對一個菜譜只能收藏一次
    unique('unique_user_recipe').on(table.userId, table.recipeId)
  ]
)
```

**為什麼這樣設計？**

- **主鍵 id**：每筆記錄的唯一識別
- **外鍵 userId, recipeId**：建立關聯，確保資料完整性
- **CASCADE 刪除**：當用戶或菜譜被刪除，相關收藏自動清理
- **索引**：加速「查某個用戶的收藏」或「查某個菜譜被誰收藏」
- **UNIQUE 約束**：資料庫層面防止重複收藏

#### 2.2 定義關聯關係（Relations）

```typescript
// favorites 與 user、recipes 的關係
export const favoritesRelations = relations(favorites, ({ one }) => ({
  user: one(user, {
    fields: [favorites.userId],
    references: [user.id]
  }),
  recipe: one(recipes, {
    fields: [favorites.recipeId],
    references: [recipes.id]
  })
}))
```

**這個做什麼用？**

- 讓 Drizzle ORM 知道表之間的關係
- 可以輕鬆做 JOIN 查詢
- 例如：查收藏列表時，同時取得菜譜詳細資訊

#### 2.3 生成遷移檔案

```bash
pnpm db:generate
```

**發生了什麼？**

- Drizzle Kit 讀取 schema.ts
- 自動生成 SQL 遷移檔案
- 檔案內容：
  ```sql
  CREATE TABLE "favorites" (
    "id" text PRIMARY KEY NOT NULL,
    "user_id" text NOT NULL,
    "recipe_id" text NOT NULL,
    "created_at" timestamp DEFAULT now() NOT NULL,
    CONSTRAINT "unique_user_recipe" UNIQUE("user_id","recipe_id")
  );
  ```

## 第四步：實作 API 路由

### 💭 思考過程

現在要實作三個 API，每個 API 要考慮：

1. **輸入驗證**：資料格式對嗎？
2. **權限檢查**：這個用戶可以做這個操作嗎？
3. **業務邏輯**：實際的操作（查詢、新增、刪除）
4. **錯誤處理**：如果出錯怎麼辦？
5. **回應格式**：返回什麼資料？

### 📝 實作步驟

創建 `src/routes/favorites.openapi.ts`：

#### 4.1 GET /api/favorites - 取得收藏列表

```typescript
app.openapi(listFavoritesRoute, async (c) => {
  // 1. 取得並驗證查詢參數
  const { page, limit } = c.req.valid('query')

  // 2. 取得當前登入用戶（由認證中間件提供）
  const user = c.get('user')

  // 3. 計算分頁偏移量
  const offset = (page - 1) * limit

  // 4. 查詢資料庫 - JOIN 取得菜譜詳情
  const data = await db
    .select({
      recipeId: favorites.recipeId,
      createdAt: favorites.createdAt,
      recipe: {
        /* 所有菜譜欄位 */
      }
    })
    .from(favorites)
    .innerJoin(recipes, eq(favorites.recipeId, recipes.id)) // JOIN
    .where(eq(favorites.userId, user.id)) // 只查自己的收藏
    .orderBy(desc(favorites.createdAt)) // 最新的在前面
    .limit(limit)
    .offset(offset)

  // 5. 計算總數
  const total = await db
    .select({ count: favorites.id })
    .from(favorites)
    .where(eq(favorites.userId, user.id))

  // 6. 返回結果
  return c.json({
    data: data.map(/* 格式化日期 */),
    pagination: { page, limit, total: total.length }
  })
})
```

**關鍵技術點：**

- **JOIN**：一次查詢同時取得收藏和菜譜資訊（效能優化）
- **WHERE**：只查詢當前用戶的資料（資料隔離）
- **分頁**：用 LIMIT 和 OFFSET 實現

#### 4.2 POST /api/favorites - 新增收藏

```typescript
app.openapi(createFavoriteRoute, async (c) => {
  const { recipeId } = c.req.valid('json')
  const user = c.get('user')

  // 1. 檢查菜譜是否存在
  const recipe = await db
    .select()
    .from(recipes)
    .where(eq(recipes.id, recipeId))
    .limit(1)

  if (recipe.length === 0) {
    return c.json({ error: 'Recipe not found' }, 400)
  }

  // 2. 檢查是否已經收藏過
  const existingFavorite = await db
    .select()
    .from(favorites)
    .where(and(
      eq(favorites.userId, user.id),
      eq(favorites.recipeId, recipeId)
    ))
    .limit(1)

  if (existingFavorite.length > 0) {
    return c.json({ error: 'Recipe already in favorites' }, 409)
  }

  // 3. 新增收藏
  const newFavorite = await db
    .insert(favorites)
    .values({
      userId: user.id,
      recipeId: recipeId,
    })
    .returning()

  return c.json({ data: /* ... */ }, 201)
})
```

**為什麼要這樣檢查？**

- **檢查菜譜存在**：防止收藏不存在的菜譜
- **檢查重複收藏**：雖然資料庫有 UNIQUE 約束，但提前檢查可以返回更友善的錯誤訊息
- **returning()**：插入後返回新建立的記錄

#### 4.3 DELETE /api/favorites/:recipeId - 移除收藏

```typescript
app.openapi(deleteFavoriteRoute, async (c) => {
  const { recipeId } = c.req.valid('param')
  const user = c.get('user')

  // 刪除收藏（只能刪除自己的）
  const deleted = await db
    .delete(favorites)
    .where(and(eq(favorites.userId, user.id), eq(favorites.recipeId, recipeId)))
    .returning()

  if (deleted.length === 0) {
    return c.json({ error: 'Favorite not found' }, 404)
  }

  return c.body(null, 204) // 204 = 成功但無內容返回
})
```

**為什麼用 AND 條件？**

- 確保只能刪除自己的收藏
- 如果用 `eq(favorites.recipeId, recipeId)` 單一條件，可能會刪除別人的收藏！

## 🎓 核心概念總結

### 1. **資料庫設計的關鍵思維**

```
問題 → 關係類型 → 表結構 → 約束條件

範例：
- 用戶收藏菜譜 → 多對多 → 中間表 favorites → UNIQUE 約束防重複
```

### 2. **API 開發的標準流程**

```
1. 定義規格（輸入/輸出格式）
2. 資料驗證（Zod Schema）
3. 權限檢查（認證中間件）
4. 業務邏輯（資料庫操作）
5. 錯誤處理（返回適當的狀態碼）
6. 返回結果（統一格式）
```

### 3. **資料隔離的重要性**

```typescript
// ❌ 錯誤：查詢所有收藏
const data = await db.select().from(favorites)

// ✅ 正確：只查詢當前用戶的收藏
const data = await db.select().from(favorites).where(eq(favorites.userId, user.id))
```

### 4. **JOIN 的使用時機**

```typescript
// 情況 1：只需要 recipeId
// 不需要 JOIN，直接查 favorites 表

// 情況 2：需要顯示菜譜名稱、類型等資訊
// 需要 JOIN recipes 表
.innerJoin(recipes, eq(favorites.recipeId, recipes.id))
```

### 5. **錯誤處理的層次**

```
1. 資料驗證錯誤 → 400 Bad Request
2. 找不到資源 → 404 Not Found
3. 重複操作 → 409 Conflict
4. 未登入 → 401 Unauthorized（中間件處理）
5. 沒有權限 → 403 Forbidden
```

## 💡 新手常見問題

**Q1: 為什麼要用 ORM（Drizzle）而不直接寫 SQL？**

- ✅ 類型安全：TypeScript 會檢查欄位名稱
- ✅ 防止 SQL 注入
- ✅ 自動生成遷移檔案
- ✅ 程式碼更易讀易維護

**Q2: 為什麼需要 Schema 驗證？**

- ✅ 防止惡意資料進入資料庫
- ✅ 提供清楚的錯誤訊息
- ✅ 自動生成 API 文檔

**Q3: UNIQUE 約束 vs 程式檢查，哪個重要？**

- ✅ 都重要！
- 資料庫 UNIQUE：最後一道防線，絕對可靠
- 程式檢查：可以返回更友善的錯誤訊息

**Q4: 什麼時候用 CASCADE 刪除？**

- ✅ 子資料沒有獨立意義時
- ✅ 例如：用戶刪除 → 收藏記錄也應該刪除
- ❌ 不適用：訂單刪除時不應該刪除商品資料
